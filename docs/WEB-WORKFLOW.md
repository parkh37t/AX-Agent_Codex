# RFP → 전략 → Wylie 제안 → 화면설계

## 실제 실행 범위

네 단계는 순차적인 생성·검토 작업이다. 독립된 다중 에이전트 실행이나 모델 재학습을 뜻하지 않는다. RFP 원문의 인용과 요구사항을 전략에 연결하고, 전략을 제안 장표에 연결한 뒤 REQ/IA/FN/SCR 산출물을 작성한다. 각 단계는 사용자가 결과를 검토하고 반영해야 다음 단계로 진행한다. 원문이 바뀌면 이후 검토 상태가 만료된다. 제외 범위와 미확인 조건은 자동으로 계약상 확정하지 않는다.

로컬 모드는 기존 공식 Codex CLI 브리지를 사용한다. API 키를 추가하지 않으며 CLI 로그인과 실제 구독 사용 가능 여부는 사용자 환경에서 별도 확인해야 한다. Wylie 참조 문서를 실제로 읽어 프롬프트에 포함하고 파일별 SHA-256과 자료 읽기 범위를 생성 이력에 남긴다.

공개 정적 모드는 AI 서버와 ChatGPT 로그인이 연결되지 않는다. 브라우저에서 TXT/MD/CSV/JSON과 텍스트 PDF를 읽고, ChatGPT에 사용자가 직접 전달할 입력 묶음을 다운로드한다. 사용자가 가져온 결과 JSON은 요청 식별자·단계·원문 인용·관계 ID·입력 변경 여부를 검사하고 미리보기 후 반영한다. 이 모드에는 고객 자료를 포함하지 않은 Wylie 방법 요약만 들어가며 해당 요약의 해시를 기록한다. 원래 Wylie 전체 스킬을 읽었다고 표시하지 않는다.

PDF는 15MB, 150쪽, 추출 텍스트 150,000자까지 처리한다. OCR과 정적 모드의 DOCX/PPTX 입력은 지원하지 않는다. 문서 내용·링크·참조 스킬은 신뢰하지 않는 자료로 취급하며 명령으로 실행하지 않는다.

## 저장과 인증

프로젝트·스냅샷은 같은 브라우저의 localStorage에 저장된다. 공유 PC의 사용자별 계정 격리가 아니다. 민감한 프로젝트는 별도 브라우저 프로필에서 다루고 JSON 백업으로 이전한다. 공개 사이트에는 토큰·로그인 기능을 넣지 않았다.

`server/tenant-boundary.ts`는 서버에서 확인한 사용자와 프로젝트·작업 소유권을 연결하는 테스트용 경계 모듈이다. 실제 서버 라우트에 연결하지 않았고, 운영 인증·영속 DB·공식 SIWC 클라이언트 등록은 미구현이다. 공식 인증 어댑터가 없으면 거부하며 테스트 신원은 운영 환경에서 거부한다.

## 로컬 검증

이미 설치된 의존성이 있는 환경에서 다음 명령을 사용한다.

```sh
npm test
npm run build
npx playwright test --config=playwright.local-review.config.ts
VITE_STATIC_HOST=true npm run build -- --base=/AX-Agent_Codex/
npx playwright test --config=playwright.pages.config.ts
```

브라우저 자동화는 합성 자료와 모의 생성 결과로 검토·오류·재시도·백업·내보내기·모바일 표시를 확인한다. 실제 AI 품질이나 실제 ChatGPT 계정 로그인을 검증한 결과가 아니다. 정적 모드에서는 API 요청과 외부 자료 전송이 없는지도 확인한다.

## 게시 경계와 다음 작업

정적 빌드의 `dist/`만 Pages 게시 대상으로 사용한다. 소스맵, 원문 문서, 인수 보고서, 로컬 로그, 계정 설정은 포함하지 않는다. 빌드 성공이나 원격 브랜치 생성은 Pages 사이트 게시 성공과 다르다. 저장소의 Pages 설정과 실제 HTTPS 접근은 별도 확인해야 한다.

1. 합성 RFP 한 건을 사용자 공식 Codex 세션에서 네 단계로 생성하고 원문 근거·제외 범위·모순 조건 보존을 검토한다.
2. 공식 App Server/SIWC 적용 가능 경로를 확정하고, 사용자별 저장소·작업·로그아웃·만료 처리를 실제 서버에 연결한다. 타 사용자 프로젝트와 작업 조회는 거부되어야 한다.
3. Pages 게시 권한과 소스를 확정한 뒤 실제 URL에서 새로고침·파일 처리·수동 입력/결과 흐름을 다시 검증한다. 자동 AI 기능은 별도 서버 연결 후 표시한다.
